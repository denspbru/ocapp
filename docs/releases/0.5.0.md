# OCApp 0.5.0 — secure PPTX templates and branding

Date: 2026-10-19

## Scope and Issue #17 acceptance mapping

This stable release delivers M7 templates, master-layout selection and bounded organization branding. M8 visual-regression infrastructure and M9 semantic mode remain out of scope.

- **Configurable template:** `converter.pptx.template.path` accepts only an absolute operator-installed local `.pptx`. Validated bytes are cached immutably and every conversion opens a fresh `XMLSlideShow`.
- **Stable failures:** missing, unreadable, invalid, untrusted, oversized and unsupported packages, unavailable layouts and invalid generated output return stable content-free diagnostics before URL/network/browser work where applicable.
- **Layout selection:** semantic aliases `blank|title|title-only|content|section|closing` resolve page hint → global alias → `content` → `blank` within the same package; ambiguous configured names fail closed.
- **Theme and compatibility:** slides retain template master/layout/theme relationships. Layout placeholders keep authored anchors/styles, prompt text is cleared, semantic titles are populated once, and no-template/no-brand geometry remains compatible.
- **Branding:** bounded PNG/JPEG logo, optional no-template colors/fonts, footer, redacted source origin/path and slide numbers share existing shape/asset/output budgets.

## Security and resource controls

Template and logo reads reject relative paths, symlinks in every path component, trusted-root escapes and replacement races. ZIP/OPC validation bounds entry count, compressed/expanded bytes and ratio; rejects duplicate, absolute and traversal names; normalizes internal targets; and rejects external relationships, macros/VBA, ActiveX, OLE/embedded packages, comments/custom XML, template notes and disguised/linked media. Logo dimensions and pixel count are checked from metadata before decode. Preflight runs under conversion capacity and operation timeout but before URL validation, DNS, navigation, network or browser acquisition. JVM-global `ZipSecureFile` limits are unchanged.

Every generated deck is validated again for package content, slide count, dimensions, finite in-slide anchors and required template relationships. Public errors and logs do not expose filesystem paths, layout names, relationship targets or page content.

## Artifact and launch

- Artifact: `ocapp-0.5.0.jar` plus SHA-256 sidecar.
- Existing HTTP endpoints and request schemas are unchanged.
- Default security mode remains fail-closed and requires a validating proxy unless unsafe mode is explicitly acknowledged.

```bash
java -jar ocapp-0.5.0.jar \
  --converter.security.proxy-url=http://proxy.internal:3128 \
  --converter.browser.binary=/usr/bin/chromium \
  --converter.browser.driver-path=/usr/bin/chromedriver
```
