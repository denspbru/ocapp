# OCApp 0.3.1

OCApp 0.3.1 is a stable corrective release for the hybrid editable/fallback PPTX export of the built-in five-page `test_report`. It preserves the 0.3.0 API, deny-by-default network posture, resource bounds, localized-fallback rules, and authoring-hints contract.

## What changed

### Hybrid extraction no longer falls back for valid inline SVG structure

The browser extractor previously rejected a valid DOM node whenever its bounding rectangle had one zero dimension and one non-zero dimension. Zero-area structural nodes inside an inline SVG, such as definitions, gradients, and stops, are valid and can still contain or support renderable descendants. Treating them as invalid geometry aborted PageModel extraction for `test_report`; with legacy fallback enabled, that failure selected the full-page rasterization path.

The extractor now rejects only non-finite or negative rectangles. Finite zero-area nodes are skipped as shapes while their descendants are still traversed. Invalid geometry remains fail-closed, and the existing block, depth, metadata, asset, coordinate, and pixel budgets are unchanged.

### Effective clipping is detected accurately

An element was previously marked clipped whenever an ancestor had an overflow mode and the intersections remained positive, even when that intersection did not reduce the element bounds. That false-positive classification could move otherwise representable text into localized raster fallback.

Clipping is now recorded only when the effective intersection actually narrows at least one edge. Real clipping, transforms, overlaps, unsupported content, unsafe assets, and all resource-limit failures still retain their existing localized or fail-closed behavior.

### The release fixture exercises the intended authoring contract

- Pages 2–5 use four valid `data-pptx-slide="break-before"` hints and export as exactly five slides.
- The contents page uses native-friendly report lines instead of flex fragments that introduced unnecessary fallback regions.
- The confidentiality line is kept inside the bounded title-page content container.
- The fixture no longer adds `data-pptx-title` placeholders where the visible `h1`/`h2` already supplies the native title. This removes duplicate or oversized semantic overlays without removing the visual headings.
- The focused regression test requires one exact native visual title on every slide, two SVG chart pictures, one native `XSLFTable`, editable native text on every slide, bounded PNG regions only, and no slide-sized picture.
- LibreOffice evidence now renders and retains PNG previews for all five PDF pages rather than page 1 only.

## Structural and visual evidence

The release gate produced a five-slide `test_report` deck with a 960 × 540 point page size:

- 67 native text shapes across the deck;
- exactly one native editable `XSLFTable` on slide 5;
- exactly two SVG chart pictures, each 337.32 × 133.33 points, on slide 3;
- five bounded PNG shapes only: four 6.67 × 6.67 point chart legend swatches and one 85.33 × 18.67 point forced localized badge;
- no picture approaching the slide dimensions and therefore no slide-sized screenshot shape;
- exactly one matching native `h1`/`h2` title on each of the five slides.

LibreOffice 26.8.0.3 converted the deck to a five-page PDF. All five 144-DPI previews were inspected: the native headings remain visible once, both charts render, the KPI/risk page retains its localized badge, and the portfolio table remains visible and editable in the PPTX structure. Evidence was regenerated under `target/test-report-0.3.1-evidence`.

## Requirements and launch

- JDK/JRE 21; Maven 3.9+ to build.
- A compatible Chrome/Chromium and ChromeDriver pair supplied by the deployment.
- LibreOffice is optional at runtime and was used only for release visual evidence.
- Production remains fail-closed in `PROXY` egress mode and requires a validating HTTP proxy plus explicit browser/driver paths.

```bash
mvn clean package
java -jar target/ocapp-0.3.1.jar \
  --converter.security.proxy-url=http://proxy.internal:3128 \
  --converter.browser.binary=/usr/bin/chromium \
  --converter.browser.driver-path=/usr/bin/chromedriver
```

The bounded Docker Compose example remains available:

```bash
mvn clean package
docker compose -f deploy/docker-compose.yml up --build
```

## Compatibility and safety

- Public API routes and response contracts are unchanged.
- Security, proxy, URL/DNS, browser-process cleanup, screenshot/output, PageModel, slide, shape, graphics, and asset bounds are unchanged.
- Valid authoring hints still cannot override security, representability, clipping, or resource checks.
- Legacy fallback remains available for genuine extraction/planning failures; `PPTX_MAX_SLIDES_EXCEEDED` still never falls back.
- Existing tracker issues remain open; this release does not change issue state.

## Known limitations

- PowerPoint itself was not part of this release environment. Evidence consists of Apache POI structural reopen plus LibreOffice/PDFBox rendering; broader cross-version PowerPoint validation remains future M8 scope.
- Selenium reported that Chrome DevTools Protocol 154 used its closest bundled mapping, version 153. The complete fail-closed browser suite passed, but upgrading Selenium when an exact CDP 154 mapping is available remains prudent.
- SVG support remains deliberately conservative. Unsupported or unsafe SVG features and Canvas content retain raster boundaries/localized fallback.
- Rendering still depends on Chromium, fonts, locale/timezone, CSP, and source-page behavior. CAPTCHA, DRM, and authenticated pages remain unsupported.
- M7 templates/branding and M8 full visual-regression governance are not part of 0.3.1.
