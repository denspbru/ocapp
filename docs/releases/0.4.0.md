# OCApp 0.4.0 — acceptance hardening

Date: 2026-10-12

## Scope and criterion mapping

This release hardens the already shipped M3/M6 implementation for Issues #13 and #16; it does not implement M7 templates, M8 validation platform, or M9 semantic mode.

- **#13 border fidelity:** PageModel now retains all four computed CSS border sides. Uniform visible solid text/container borders with finite bounded nonnegative width and an opaque parseable color remain native; CSS px width is mapped to PPT points. Non-uniform, dashed, dotted, complex, translucent, invalid, or oversized borders use localized screenshot fallback without dropping backgrounds or duplicating content.
- **#13 text/image evidence:** POI reopen tests assert bold, italic, alignment, line spacing, native border width/color, mapped placement, image aspect ratio, hyperlinks, and localized crop dimensions. Safe bounded embedded raster assets remain native. External/non-embedded assets are not fetched again and conservatively use screenshot fallback.
- **#16 hint presence:** presence of any recognized data-pptx-* attribute is retained independently from its normalized effect. In particular, data-pptx-ignore="false" and data-pptx-keep-together="false" preserve ocapp.authoring-hints.contract=1 while leaving content/planning unchanged. No-hint pages remain unchanged and warning budgets remain bounded.

## Architecture and safety

The Chromium extraction -> immutable PageModel -> SmartPaginationPlanner/EditableRenderPlanner -> Apache POI boundary remains renderer-independent. The change adds no network fetch, external converter, hidden AI call, or request-level limit bypass. Existing URL/egress policy, browser lifecycle/cancellation ownership, capture/asset/shape/output limits, localized fallback suppression, and legacy fallback behavior are preserved.

## Fidelity policy

POI structural assertions use exact normalized values for semantic properties and ±0.01 pt for placement/size/border width, at most 0.1% aspect-ratio error, and ±0.5 percentage point for line spacing. OOXML preserves the requested font family, but an unavailable font may be substituted by the viewing application; release fixtures use installed Arial-compatible fonts. Substitution that causes reflow beyond the fixture tolerance requires localized fallback or an explicit documented manual exception.

## Launch and compatibility

- Artifact version and filename: 0.4.0 / target/ocapp-0.4.0.jar.
- Existing endpoints and request schema are unchanged.
- Hybrid editable rendering remains the default; converter.pptx.editable-enabled=false remains the compatibility path.
- M7/M8 remain targeted for 0.4.x; M9 moves to 0.5.
