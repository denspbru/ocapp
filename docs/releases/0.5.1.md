# OCApp 0.5.1 — PPTX layout validation and visual regression

Date: 2026-10-26

## Scope and Issue #18 acceptance mapping

This stable patch release delivers M8 while preserving the `0.5.0` HTTP and successful PPTX binary contract.

- **Every generated PPTX is validated:** visual and editable renderers serialize the final package, validate bounded OPC/package invariants, reopen it with Apache POI and run deterministic layout validation before returning bytes.
- **Stable bounded diagnostics:** content-free `PPTX_LAYOUT_*` codes cover out-of-slide geometry, text overflow, unintended overlap, tiny fonts, empty slides, low-resolution images, broken references, unavailable measurements and diagnostic truncation.
- **Compatibility policy:** objective corruption, broken references and invalid/out-of-slide geometry remain blocking through sanitized `PPTX_TEMPLATE_OUTPUT_INVALID`; renderer/font-dependent quality findings remain warnings throughout `0.5.x`.
- **Metrics and privacy:** fixed-field mode, shape-role, fallback-area, pagination and diagnostic metrics contain no page or notes text, URLs, filesystem/relationship paths, arbitrary names or image bytes.
- **Representative coverage:** existing real-browser fixtures cover text, native tables, SVG, Canvas, mixed editable/fallback content and M7 templates/branding. Speaker notes remain preserved but are excluded from visible-layout diagnostics.
- **Golden-image regression:** the isolated `pptx-visual-regression` profile uses exact-version local LibreOffice, fixed 144-DPI PDFBox rasterization and checksum-protected synthetic baselines. Tests never rewrite baselines; failures retain bounded candidate/diff metadata below `target`.

## Security and resource controls

Layout scans enforce deterministic limits for diagnostics, shapes, text shapes, images and overlap comparisons. Overlap analysis excludes intentional visual/branding, background, placeholder and explicit fallback/native relationships. LibreOffice remains test-only: unique temporary profiles, invalid network proxies, bounded captured logs and PDF output, hard timeout, repeatedly discovered process-tree termination, survivor verification and cleanup on success and failure.

## Artifact and launch

- Artifact: `ocapp-0.5.1.jar` plus SHA-256 sidecar.
- Existing HTTP endpoints, request schemas, MIME type and download filename behavior are unchanged.
- Default security mode remains fail-closed and requires a validating proxy unless unsafe mode is explicitly acknowledged.

```bash
java -jar ocapp-0.5.1.jar \
  --converter.security.proxy-url=http://proxy.internal:3128 \
  --converter.browser.binary=/usr/bin/chromium \
  --converter.browser.driver-path=/usr/bin/chromedriver
```
