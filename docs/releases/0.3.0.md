# OCApp 0.3.0

OCApp 0.3.0 is the first stable release of the hybrid editable/fallback PPTX pipeline. It combines M3–M6 while preserving the existing API, deny-by-default network posture, bounded resource model, and screenshot compatibility paths.

## Highlights

### M3 — editable text and images ([#13](https://github.com/denspbru/ocapp/issues/13))

- Headings, paragraphs, simple spans, styles, alignment, spacing, and hyperlinks are emitted as native PowerPoint text shapes when representation is safe.
- Safe embedded raster images become native pictures with CSS placement and aspect ratio preserved.
- Unsupported CSS, clipping, transforms, overlap groups, or ambiguous assets use a localized crop from the same bounded full-page screenshot rather than degrading the whole slide.
- A single CSS-pixel-to-point mapping is used for native and fallback content, avoiding gaps and duplicate rendering.

### M4 — editable lists and tables ([#14](https://github.com/denspbru/ocapp/issues/14))

- Ordered and unordered lists are mapped to native bullets/numbering with nesting through level 8.
- Supported HTML tables become editable `XSLFTable` objects with proportional dimensions, fills, borders, alignment, and supported merges.
- Long tables split only at row boundaries and repeat contiguous leading header rows.
- Wide, dense, complex, or cross-page-rowspan tables follow documented bounds and fall back to localized screenshots.

### M5 — SVG, Canvas, and ECharts ([#15](https://github.com/denspbru/ocapp/issues/15))

- Compatible inline SVG is sanitized through fail-closed browser and Java allowlists and embedded as an SVG picture with aspect ratio and transparency preserved.
- Canvas is exported locally to PNG; ECharts is exported locally to bounded PNG or SVG after readiness.
- Export scale, background, format, pixel count, and decoded bytes are configurable and bounded.
- Active/external/malformed SVG, tainted Canvas, and missing or failed ECharts use a localized screenshot fallback. Page data is never sent to a third-party conversion service.

### M6 — versioned authoring hints ([#16](https://github.com/denspbru/ocapp/issues/16))

- Adds authoring contract v1 for `data-pptx-slide`, `data-pptx-title`, `data-pptx-ignore`, `data-pptx-keep-together`, `data-pptx-notes`, `data-pptx-layout`, and `data-pptx-render`.
- The contract version is recorded as PPTX custom property `ocapp.authoring-hints.contract=1`.
- Explicit valid hints take precedence over automatic heuristics, while security, representability, and resource checks always take precedence over hints.
- Pages without hints retain automatic pagination and hybrid rendering behavior.
- Invalid/conflicting hints produce bounded, content-free warnings or stable validation errors; they do not expose page content in warning metadata.

## Security, fallback, and resource behavior

- Production startup remains fail-closed in `PROXY` egress mode until a validating HTTP proxy is configured. URL/DNS checks and DevTools interception remain defense in depth, not a substitute for the network boundary.
- Browser readiness, navigation, redirect chains, cleanup, output, screenshot, geometry, slides, shapes, metadata, graphics, and PageModel allocations remain bounded.
- `render="native"` cannot bypass SVG sanitization, unsupported-content fallback, or any resource limit. `render="image"` forces one localized image region and suppresses duplicate descendants.
- Extraction/planning failures can retain the documented legacy fixed-slice fallback when enabled; `PPTX_MAX_SLIDES_EXCEEDED` never falls back.
- No conversion result is persisted by the service.

## Requirements and launch

- JDK/JRE 21 and Maven 3.9+ to build.
- A compatible Chrome/Chromium and ChromeDriver pair supplied by the deployment.
- LibreOffice is optional at runtime and was used only for release visual gates.
- Production requires a validating HTTP proxy and explicit browser/driver paths.

```bash
mvn clean package
java -jar target/ocapp-0.3.0.jar \
  --converter.security.proxy-url=http://proxy.internal:3128 \
  --converter.browser.binary=/usr/bin/chromium \
  --converter.browser.driver-path=/usr/bin/chromedriver
```

The repository also includes a bounded Docker Compose example:

```bash
mvn clean package
docker compose -f deploy/docker-compose.yml up --build
```

## Release build evidence

The release candidate is gated under JDK 21 by:

- `mvn clean verify`, including strict JaCoCo thresholds: instruction/line at least 90%, branch at least 70%, method/class exactly 100%;
- fail-closed real-browser Failsafe execution with a compatible Chrome/ChromeDriver pair;
- LibreOffice/PDFBox visual gates for the mixed M3/M4 deck, M5 graphics deck, and M6 hints deck;
- Apache POI structural reopen, JAR manifest/content inspection, and SHA-256 verification.

Exact test, coverage, browser, office, artifact, and checksum values are recorded in the published GitHub release after the gates complete.

## Acceptance mapping

### #13 — editable text and images

- **Met:** editable native text; clickable links; native images with aspect ratio/placement; localized fallback for unsupported/ambiguous regions; mixed native/fallback structural and LibreOffice visual fixture.

### #14 — lists and tables

- **Met:** ordered/unordered markers and supported nesting; editable native table cells; whole-row pagination; repeated leading headers; documented bounds and localized fallback for wide/complex tables.

### #15 — SVG, Canvas, and ECharts

- **Met:** sanitized SVG aspect ratio/transparency; delayed Canvas/ECharts without clipping; bounded configurable scale; safe fallback for tainted Canvas/failed charts; no third-party conversion upload.

### #16 — authoring hints

- **Met:** documented/versioned v1 contract; explicit-hint precedence; unchanged automatic behavior without hints; bounded safe invalid/conflict handling; fixture coverage for every supported attribute and precedence conflicts.

Issues #13–#16 intentionally remain open; this release does not change tracker state without separate authorization.

## Known risks and limits

- PowerPoint itself is not part of the automated release environment. Apache POI structural reopen and LibreOffice rendering are the release evidence; broader cross-version PowerPoint validation remains future M8 scope.
- SVG support is deliberately conservative; unsupported SVG features and all Canvas content use raster boundaries/fallback as documented.
- Rendering depends on Chromium, fonts, locale/timezone, CSP, and source-page behavior. CAPTCHA, DRM, and authenticated pages are unsupported.
- Application URL checks are not a network isolation boundary; operators must maintain the validating proxy and deployment firewall/container isolation.
- Selenium/CDP may allocate intermediate objects internally, so JVM/container limits must be sized with concurrency and capture limits.
- M7 templates/branding and M8 full visual-regression governance are not included in 0.3.0.
